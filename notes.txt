The detection head always sees the current frame’s BEV features, modulated by a gate that encodes history.

def build_seq_loader(cfg, logger, workers, seq_len, stride):
    dataset_cfg = cfg.DATA_CONFIG
    class_names = cfg.CLASS_NAMES

    train_set = NuScenesSeqDataset(
        dataset_cfg=dataset_cfg,
        class_names=class_names,
        training=True,
        root_path=None,
        logger=logger,
        seq_len=seq_len,
        stride=stride,
        nusc_version=dataset_cfg.VERSION,
        nusc_dataroot=dataset_cfg.DATA_PATH,
    )

    train_loader = DataLoader(
        train_set,
        batch_size=1,
        shuffle=True,
        num_workers=min(workers, cfg.OPTIMIZATION.NUM_WORKERS),
        pin_memory=True,
        collate_fn=collate_seq,
        drop_last=False,
    )

    return train_set, train_loader

The problem you're hitting is not that L2 is wrong for your use case — it's that your query encoder outputs have large unconstrained magnitudes making L2 distances explode at initialisation. STCN doesn't have this problem because their key encoder is trained from scratch on ImageNet features that happen to be well-scaled.
The real fix is to normalise the keys at write time AND queries at read time (making it cosine) but use a learnable temperature instead of the hardcoded 0.01:
pythonself.attn_temp = nn.Parameter(torch.tensor(0.1))  # learnable temperature

S = torch.bmm(q_blk, k_flat_n.T) / self.attn_temp.clamp(min=0.01)
This gives the model freedom to find the right scale rather than you hardcoding it.
